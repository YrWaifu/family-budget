# Цель проекта

Приложение предназначено для двух человек, которые ведут общий бюджет.

Основной сценарий использования — с телефона. Добавление расхода должно занимать несколько секунд и требовать минимум действий.

Визуально приложение должно быть вдохновлено CoinKeeper:

* яркие круглые иконки категорий;
* крупная сумма;
* удобный выбор категории одним нажатием;
* ощущение простого мобильного приложения;
* наглядная круговая диаграмма расходов;
* плавные анимации;
* приятные карточки;
* чистый современный интерфейс.

Не копируй CoinKeeper один в один, не используй его название, логотип, изображения или другие защищённые материалы. Сделай самостоятельный дизайн с похожей концепцией быстрого визуального управления финансами.

Рабочее название проекта: `family-budget`.

Интерфейс полностью на русском языке.

Основная валюта: российский рубль, символ `₽`.

# Авторизация

Сложная пользовательская система не нужна.

Реализуй простой и безопасный вариант:

* есть два локальных пользователя;
* пользователь выбирает профиль при входе;
* у каждого профиля есть имя и PIN-код;
* PIN хранится только в виде безопасного хеша;
* после входа выдаётся HTTP-only session cookie;
* сессия хранится на backend;
* оба пользователя видят один общий бюджет;
* имя автора операции сохраняется автоматически;
* в интерфейсе автора можно не показывать по умолчанию;
* должна быть возможность выйти из аккаунта.

При первом запуске приложение должно предложить создать два профиля.

Не используй OAuth, email, SMS, регистрацию и восстановление пароля.

# Главный пользовательский сценарий

Пользователь открывает приложение и сразу видит главный экран.

На главном экране:

* общая сумма расходов за текущий месяц;
* остаток месячного бюджета, если бюджет задан;
* круговая диаграмма расходов по категориям;
* крупные круглые кнопки категорий;
* последние операции;
* нижняя мобильная навигация;
* большая заметная кнопка добавления расхода.

Добавление расхода должно быть максимально быстрым.

Оптимальный сценарий:

1. пользователь нажимает на категорию;
2. открывается цифровая клавиатура;
3. пользователь вводит сумму;
4. нажимает «Готово».

Дата автоматически устанавливается текущая.

Комментарий необязательный.

Нужно также поддержать альтернативный сценарий:

1. кнопка `+`;
2. сумма;
3. категория;
4. необязательный комментарий;
5. сохранение.

После добавления:

* операция сразу появляется в списке;
* диаграммы обновляются;
* показывается короткое подтверждение;
* форма закрывается;
* интерфейс не перезагружается.

* автоматическое предложение комментария на основе последних операций выбранной категории.

# Порядок выполнения

Сначала:

1. проанализируй требования;
2. зафиксируй краткий технический план в `PLAN.md`;
3. создай структуру репозитория;
4. реализуй backend;
5. реализуй frontend;
6. добавь миграции;
7. добавь Docker;
8. добавь тесты;
9. запусти проверки;
10. исправь найденные ошибки;
11. обнови README.

Не останавливайся после создания плана.

Не проси меня вручную дописывать обязательные части проекта.

После каждого логического этапа делай отдельный git commit с понятным conventional commit message, если работа идёт в git-репозитории.

Примеры:

```text
chore: initialize project structure
feat(api): add authentication and setup
feat(api): add transaction management
feat(api): add analytics endpoints
feat(web): add mobile expense flow
feat(web): add dashboard and analytics
feat: add goals and recurring payments
chore: add docker deployment
test: cover critical user flows
docs: add deployment guide
```
